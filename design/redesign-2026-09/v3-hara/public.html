用 Markdown 写作

2026 年 7 月 3 日8 分钟阅读指南写作

文章与随想共用一条 Markdown 管线：可移植、可版本化、对 AI 友好。这篇文章记录这条管线的设计取舍，以及在 Myself 里可以用到的全部语法。

为什么是 Markdown

富文本编辑器把格式藏进不可见的标签里；Markdown 把格式写在纸面上。前者需要一个编辑器才能打开，后者用任何一台机器的任何一个文本编辑器都能读。当你十年后想把这些文字搬到别处，只有纯文本还会毫发无损。

好的格式不是被看见的，而是被读到的。—— 写在第一次迁移之后

另一个原因是 AI。外部助手通过 API 中心 投稿时，Markdown 是它们最熟悉的输出格式——不需要任何转换层，写出来即可发布。

一条管线

文章与随想在存储层完全相同：一段 Markdown 正文加少量元信息。渲染层也只有一个入口 utils/markdown.ts，负责语法解析、代码高亮与 TOC 锚点生成。

代码块与语言角标

代码块右上角会显示语言名，高亮在离线环境下由 highlight.js 完成：

// 通过 APIKey 发布一篇文章
func (h *Handler) CreatePost(w http.ResponseWriter, r *http.Request) {
    key := r.Header.Get("X-Api-Key")
    if !h.auth.Verify(key) {
        http.Error(w, "unauthorized", http.StatusUnauthorized)
        return
    }
    var in PostInput
    json.NewDecoder(r.Body).Decode(&in)
    h.store.Posts.Create(r.Context(), in.Markdown())
}

  • 让 AI 助手试投第一篇随想

可移植与可版本化

所有正文都是 UTF-8 文本，意味着它们可以放进 Git、可以 diff、可以在任何编辑器里重写。数据中心的备份只是把 SQLite 与上传目录打成一个 zip——没有私有格式，没有锁定。

  • 备份 = 数据库 + uploads，一个 zip
  • 导出 = 每篇文章一个 .md，front-matter 存元信息
  • RSS 直接从 Markdown 渲染，无需二次维护

结语

Markdown 不是最强大的格式，但它是最诚实的：你看见的就是你写下的。对一个想写很多年的博客来说，这比任何功能都重要。
